First preview of Slipstream: the download engine with a command-line client. There is no app window and no browser catching yet; those come next.

## What works
- **Many connections per file**: starts with one, doubles up to 8 while that actually adds speed, and splits the biggest remaining piece for each new connection. On servers that limit each connection this is several times faster than a browser; on servers that don't, it stays at one or two connections.
- **Resume after anything**: Ctrl+C, a crash, a reboot or a dropped network. Run the same command again and it continues where it stopped. A file that changed on the server is detected instead of being glued together.
- **Retries** with backoff, `429 Too Many Requests` handling, racing a stalled connection near the end.
- **Speed limit** (`--limit 2M`) and connection count (`-c 4`).
- Correct file names, including `Content-Disposition` and Unicode names.

## Use it
```
slipstream get https://example.com/big-file.iso -d Downloads
slipstream get URL -c 4 --limit 5M
slipstream get URL -H "Cookie: session=abc"
```
Run the same command again to resume. Set `SLIPSTREAM_DEBUG=1` to see why it adds or drops connections.

## Downloads
- Windows 10/11 x64: `slipstream-v0.1.0-x86_64-pc-windows-msvc.zip`
- Linux x64 (glibc 2.35+, e.g. Ubuntu 22.04+, Debian 12+, Fedora 36+): `slipstream-v0.1.0-x86_64-unknown-linux-gnu.tar.gz`

Each archive has a `.sha256` file to check it. The Windows build is not code-signed yet, so SmartScreen or Smart App Control may warn about or block it.

## Known limits
- Preview: command line only, one download per command.
- HTTP(S) only; no FTP, no proxy settings, no video streams yet.
- Benchmarks and test results: `docs/benchmarks.md`.
